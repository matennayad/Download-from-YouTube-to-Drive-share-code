# 📖 מדריך הקמה — טופס חיפוש מאוחד (יוטיוב + מאקו + כאן 11)

המדריך הזה מקים טופס חיפוש חדש שמאפשר למשתמשים מאושרים לחפש תוכן בשלוש הפלטפורמות — גם כשנטפרי חוסם את אתרי המקור — ולקבל במייל תוצאות עם כפתורי הורדה שמעבירים לטופס ההורדות הקיים עם הכל ממולא.

## איך זה עובד (השרשרת המלאה)

```
משתמש ממלא טופס גוגל (חיפוש + מקורות)
      ↓
Apps Script פונה לשרת: POST /search
      ↓
השרת מחפש: יוטיוב דרך yt-dlp + מאקו וכאן דרך Bing (עם site:)
      (שלושת המקורות נשלפים במקביל; שאילתא חוזרת תוך 10 דקות מוחזרת ממטמון)
      ↓
מייל מעוצב עם כרטיסי תוצאות (תגית מקור לכל תוצאה)
      ↓
לחיצה על "הורד וידאו/אודיו" ← טופס ההורדות הקיים נפתח ממולא
(קישור + סוג הורדה + המייל של המשתמש) — המשתמש רק לוחץ "שליחה"
      ↓
מערכת ההורדות הרגילה: מאושרים → מכסות → נטפרי → מטמון → דרייב
```

**כרטיסי עונה:** תוצאה שהיא עמוד עונה של כאן (`.../p-X/sN/`) או של מאקו
(`.../slug-sN/`) מורחבת במייל לכרטיס עם כפתור לכל פרק בעונה — השרת
מספק את רשימת הפרקים דרך `POST /episodes` (מקבל גם את מפתח החיפוש),
והעונה של מאקו נחלצת מהקישור עצמו בלי פרמטר נוסף.

**נקודה חשובה:** כפתור ההורדה פותח את **טופס ההורדות הקיים** שלך — אותו טופס שכבר מחובר לשירות. לא נוצר טופס הורדות חדש,
והסקריפט של טופס ההורדות **לא שונה בכלום**.

## שלב 1: יצירת הטופס (~5 דקות)

1. פתח [forms.google.com](https://forms.google.com) → **טופס ריק חדש**
2. כותרת הטופס: **חיפוש תוכן להורדה**
3. תיאור: `חפשו סרטונים וסדרות ביוטיוב, מאקו וכאן 11 — ותקבלו את התוצאות במייל`
4. צור **שאלה 1** — שאלת טקסט קצר:
   - כותרת: `מה לחפש?`
   - סוג: **קלט טקסט קצר**
5. צור **שאלה 2** — שאלת תיבות סימון:
   - כותרת: **איפה לחפש?** (המילה "איפה" חובה — הסקריפט מזהה אותה)
   - סוג: **תיבות סימון**
   - אפשרויות (בדיוק כך):
     - `יוטיוב`
     - `מאקו`
     - `כאן 11`
   - הפעל "נדרש"
6. ⚙️ הגדרות הטופס:
   - **אספו כתובות אימייל** → ✓ אסוף כתובות אימייל מאומתות (חובה!)
   - הגבל לתשובה אחת — לפי הצורך
7. לחץ **שלח** → העתק את קישור הטופס (forms.gle/...)

### קבלת מזהה הטופס

פתח את הטופס לעריכה — ב-URL יופיע משהו כמו:
```
https://docs.google.com/forms/d/1AbCdEfGhIjKlMnOpQrStUvWxYz1234567890/edit
```
המזהה הוא החלק הארוך בין `/d/` ל-`/edit`.

## שלב 2: חיבור הסקריפט (~5 דקות)

1. מערכת הטופס → שלוש הנקודות ⋮ → **עורך סקריפטים** (נפתח חלון חדש)
2. מחק את הקוד הקיים, הדבק את כל התוכן של הקובץ
   `apps-script/unified-search/קוד.js` מהחבילה
3. בראש הקובץ מלא:
   ```javascript
   var FORM_ID = "המזהה_שהעתקת_בשלב_1";
   var APPROVED_SHEET_ID = "מזהה הגיליון של מערכת ההורדות";
   ```
   וגם את כתובות השרת (`SEARCH_SERVER_URL`, `KAN_EPISODES_URL`) ואת פרטי טופס ההורדות
   (`DOWNLOAD_FORM_BASE_URL` + שני מזהי ה-entry) — ראו המדריך הראשי.
4. שמור 💾 (Ctrl+S), תן לפרויקט שם: `unified-search-form`

### מפתח ה-API

5. ⚙️ **Project Settings** (בסרגל השמאלי) → סמן ✓ **"Show appsscript.json manifest"**
6. חזור לעורך → בסרגל השמאלי לחץ על **appsscript.json** והחלף בתוכן של הקובץ
   `apps-script/unified-search/appsscript.json` מהחבילה.
   צור גם קובץ HTML חדש בשם `admin_dashboard` (➕ → HTML) והדבק בו את `admin_dashboard.html`.
7. בסרגל השמאלי: **Project Settings** → גלול ל-**Script Properties** →
   **Add script property**:
   - **Property**: `API_KEY`
   - **Value**: המפתח של השירות (אותו API_KEY שמוגדר ב-Railway)
   - שמור

## שלב 3: אישור הרשאות והפעלה (~3 דקות)

1. בעורך, בחר בפונקציה **`checkSetup`** מהתפריט הנפתח → **Run**
2. גוגל יבקש אישור הרשאות → **Review permissions** → בחר את החשבון →
   "Google hasn't verified this app" → **Advanced** → **Go to ... (unsafe)** →
   **Allow** (זה הסקריפט שלך — בטוח)
3. ביומן ההרצה (Execution log) אמור להופיע: `✅ הכל תקין!`
   - אם יש ❌ — תקן לפי ההודעה והרץ שוב
4. בחר **`checkGmailApi`** → Run — זו הבדיקה שקובעת אם מסלול המייל באמת עובד.
   - אם מופיע `✅ Gmail API פעיל ותקין` — מעולה, המשך לשלב הבא.
   - אם מופיע `❌ הגורם: Gmail API כבוי בפרויקט ה-GCP` — ה-API לא מופעל בפרויקט
     שאליו משויך הסקריפט. פתח את **Project Settings → GCP Project**: אם כתוב שם
     `Default` (פרויקט אוטומטי של Apps Script) לחץ **Change project** ובחר/צור
     פרויקט GCP רגיל, ואחר כך **APIs & Services → Library → Gmail API → Enable**.
     חשוב: `grantGmailScope` **לא** פותר את זה — אין מה לאשר, ה-API פשוט כבוי.
   - אם מופיע `❌ חסרה הרשאת OAuth` — הרץ **`grantGmailScope`** ואשר את המסך.
   - אם במקום מסך האישור גוגל מציגה **"הגישה חסומה / access_denied —
     האפליקציה בבדיקה"** — זו לא תקלה במערכת: הפרויקט החדש יוצר אפליקציית
     OAuth במצב "בדיקה", ורק חשבונות שסימנת כבודקים יכולים לאשר. בקונסולה:
     **APIs & Services → OAuth consent screen (Google Auth Platform) →
     Audience → Test users → Add users** → החשבון שלך → Save. ואז הרץ שוב.
     כדאי גם לוודא ש-**Gmail API** מופעל (APIs & Services → Library → Gmail API → Enable).
5. בחר **`fixTriggers`** → Run
   - אמור להופיע: `✅ נוצר טריגר חדש על שליחת הטופס`
6. בחר **`testSearchAndEmail`** → Run
   - יישלח לך מייל בדיקה עם תוצאות חיפוש אמיתיות של "בואו לאכול איתי" 🎉
   - בדוק שהכפתורים "הורד וידאו/אודיו" פותחים את טופס ההורדות ממולא

## שלב 4: בדיקה קצה-לקצה

1. פתח את קישור הטופס החי (forms.gle/...)
2. מלא: `שמחה` (או כל דבר) + סמן `יוטיוב` ו-`כאן 11`
3. שלח → תוך דקה-שתיים יגיע המייל עם התוצאות
4. לחץ על כפתור הורדה → טופס ההורדות נפתח ממולא → **שליחה**
5. עוד רגע תקבל מייל סטטוס ממערכת ההורדות, והקובץ יעלה לדרייב

## פתרון בעיות

| תופעה | סיבה | פתרון |
|---|---|---|
| `FORM_ID (מזהה הטופס החדש)` ב-checkSetup | לא מילאת FORM_ID | מלא בראש הקובץ |
| 401 בחיפוש | API_KEY שגוי/חסר | בדוק Script Properties |
| המייל לא מגיע | הטריגר חסר | הרץ fixTriggers שוב |
| "איפה לחפש" לא מזוהה | כותרת השאלה שונתה | החזר את המילה "איפה" לכותרת |
| תוצאות מאקו/כאן = 0 | אין תוצאות במנועים | נסה ניסוח אחר; בדוק בגיליון את עמודת הסטטוס |
| "לא מאושר" אין כפתורים במייל? | המייל שלך לא בגיליון המאושרים | הוסף את המייל לגיליון "מאושרים" |
| ביומן: `Gmail API HTTP 403 ... has not been used in project` | Gmail API כבוי בפרויקט ה-GCP של הסקריפט | הרץ `checkGmailApi` ופעל לפי ההוראות (Change project + Enable) — `grantGmailScope` לא עוזר כאן |
| ביומן: `Service invoked too many times for one day: email` | נגמרה מכסת המיילים היומית של החשבון (100 ב-gmail.com) | המתן לאיפוס (≈10:00 בישראל) או הפעל את Gmail API כמסלול הראשי |
| בדפדפן: "הגישה חסומה: תהליך האימות לא הושלם" / `403: access_denied` — האפליקציה בבדיקה | החשבון שלך לא ברשימת הבודקים של פרויקט ה-GCP החדש | OAuth consent screen → Audience → Test users → Add users → החשבון שלך → Save, ואז הרץ שוב |
| בדפדפן: "Google hasn't verified this app" | זה הסקריפט שלך, לא אפליקציה זרה | Advanced / מתקדם → Go to UnifiedSearch (unsafe) → Allow |
| המייל לא מגיע בלי שגיאה ביומן | השליחה עברה אבל נחתה בספאם / נדחתה אצל הנמען | בדוק ספאם; הרץ `checkGmailApi` כדי לשלול תקלת API |

## מה יש בפועל בכל שכבה

| רכיב | איפה | מה נעשה בו |
|---|---|---|
| טופס חיפוש | Google Forms (חדש) | חיפוש + בחירת מקורות + מייל אוטומטי |
| סקריפט חיפוש | Apps Script חדש | פנייה ל-/search + מייל תוצאות + לוג |
| שרת | Railway (הקיים) | `/search` מאוחד: יוטיוב + מאקו + כאן |
| טופס הורדות | Google Forms (הקיים) | **לא נשונה** — מקבל קישורים ממולאים |
| סקריפט הורדות | Apps Script (הקיים) | **לא שונה** — כבר תומך במאקו/כאן/יוטיוב |
| שליחת מיילים | Gmail API + MailApp | Gmail API כמסלול ראשי + MailApp (100 נמענים ביום) כגיבוי — בלי שירות חיצוני |

## הערה על מכסת המיילים

השליחה עוברת קודם ב-Gmail API (מגבלת השליחה הרגילה של Gmail), ואם הוא נכשל —
נופלת אוטומטית ל-MailApp, שמוגבל ל-**100 נמענים ביום** בחשבון gmail.com.
החשוב לזכור: המכסה נספרת לחשבון, לא לפרויקט — גם סקריפט ההורדות שולח מאותה
מכסה של 100, ולכן אם אחד מהם התרוקן, גם השני ייכשל עד האיפוס (≈10:00 בישראל).

**חשוב:** ה-Gmail API חייב להיות מופעל בפרויקט ה-GCP שאליו משויך הסקריפט.
אם הסקריפט משויך לפרויקט ה-default האוטומטי של Apps Script, אי אפשר להפעיל בו
APIs — צריך לחבר פרויקט GCP רגיל (Project Settings → GCP Project → Change project).
הריצו `checkGmailApi` כדי לדעת בדיוק מה מצב החשבון ומה חסר.
